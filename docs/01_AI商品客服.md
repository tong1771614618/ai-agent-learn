## 项目 1: AI 商品客服 — 学习笔记

### 浓缩工作流程

```
用户在网页输入: "有没有适合夏天跑步的鞋？"
        │
        ▼
┌─── Laravel (PHP) ────────────────────────────────────┐
│  ProductSearchController.php                         │
│  ① 接收 POST /api/v1/products/search                │
│  ② 调用 AiService.php → HTTP POST → Python         │
└──────────────────────┬───────────────────────────────┘
                       │ HTTP JSON
                       ▼
┌─── FastAPI (Python, port 8001) ──────────────────────┐
│  ③ prompts.py: 组装 System Prompt + Few-shot 示例    │
│  ④ ai_service.py: 调用 Qwen API                     │
│     - messages = [system, user]                      │
│     - temperature = 0.1 (低随机性)                   │
│     - response_format = json_object (强制JSON)       │
│  ⑤ schemas.py: Pydantic 校验返回的 JSON              │
└──────────────────────┬───────────────────────────────┘
                       │ Qwen API 返回
                       ▼
  ┌─────────────────────────────────────────────────┐
  │  {                                              │
  │    "intent": "search",                          │
  │    "keywords": ["跑步", "鞋", "夏天"],           │
  │    "category": "running",                       │
  │    "budget_max": null,                          │
  │    "brands": []                                 │
  │  }                                              │
  └──────────────────────┬──────────────────────────┘
                         │ HTTP JSON 返回
                         ▼
┌─── Laravel (PHP) ────────────────────────────────────┐
│  ⑥ 用结构化数据查 MySQL:                            │
│     Product::active()                               │
│       ->inCategory("running")                       │
│       ->matchKeywords(["跑步","鞋","夏天"])          │
│  ⑦ 返回匹配商品列表                                 │
└──────────────────────┬───────────────────────────────┘
                       │ JSON
                       ▼
            网页展示: AI 解析结果 + 商品卡片
```

### 网页展示结构（API 响应 → 视觉呈现）

网页 `demo/project1.html` 收到 API 返回的 JSON 后，分两层展示：

```
API 返回的完整 JSON:
{
  "ai_analysis": {           ← 第一层: AI 解析面板（蓝色背景框）
    "intent": "search",
    "keywords": ["跑步", "鞋", "夏天"],
    "category": "running",
    "budget_max": null,
    "brands": []
  },
  "products": [...],          ← 第二层: 商品卡片列表
  "total": 8

```

**第一层：AI 解析面板**（页面中浅蓝色区域）

让用户直观看到"LLM 到底做了什么"：

```
┌─────────────────────────────────────────┐
│  意图:  search                          │  ← a.intent
│  分类:  running                         │  ← a.category（null 时显示"未识别"）
│  关键词: 跑步, 鞋, 夏天                  │  ← a.keywords.join(', ')
│  预算:  ≤ ¥500                          │  ← a.budget_max（null 时不显示这行）
│  品牌:  Nike, Adidas                    │  ← a.brands（空数组时不显示这行）
└─────────────────────────────────────────┘
```

> 学习要点：这个面板的展示逻辑体现了项目 1 的核心认知——
> LLM 只是把自然语言翻译成结构化数据，你可以"看到"翻译结果。

### 7 个核心 AI 概念速查

| 概念                 | 一句话解释                         | 代码位置                         |
| ------------------ | ----------------------------- | ---------------------------- |
| System Prompt      | 设定 LLM 的身份和行为规则，用户不可见         | prompts.py                   |
| User Prompt        | 用户的实际输入                       | ai_service.py messages[1]    |
| Few-shot Prompting | 在 Prompt 中给几个输入→输出示例，让 LLM 模仿 | prompts.py 示例部分              |
| Structured Output  | 让 LLM 返回固定格式的 JSON 而不是自由文本    | prompts.py + response_format |
| Temperature        | 控制输出随机性，0.1=稳定，0.7=灵活         | ai_service.py                |
| Token              | LLM 处理文字的最小单位，消耗=费用           | ai_service.py usage          |
| 核心认知               | LLM 不做业务逻辑，只把自然语言转成结构化数据      | ProductSearchController.php  |

### 关键代码片段

**Prompt 双保险：**
```python
# 第一道保险: Prompt 里要求
"只返回 JSON，不要任何其他文字"

# 第二道保险: API 参数强制
response_format={"type": "json_object"}
```

**Temperature 选择：**
```python
temperature=0.1   # 结构化提取、分类任务 → 稳定优先
temperature=0.7   # 开放式对话、创意写作 → 灵活优先
```

## 课堂作业

### 作业 1: 修改 System Prompt（理解 Prompt 如何影响输出）

打开 `python_service/prompts.py`，完成以下修改：

1. 在 ParsedQuery schema 中新增一个字段 `urgency`（紧急程度），值为 "high" / "medium" / "low"
2. 在 System Prompt 中添加 `urgency` 字段的说明
3. 添加一个新的 Few-shot 示例，展示高紧急程度的查询

**思考题：** 修改 Prompt 后，用"急！我明天比赛需要一双跑鞋"测试，观察 urgency 是否正确识别。如果去掉 Few-shot 示例中的"急"类示例，LLM 还能正确识别吗？

### 作业 2: 调整 Temperature（理解温度对输出的影响）

打开 `python_service/ai_service.py`，完成以下实验：

1. 把 `temperature` 从 0.1 改成 1.0
2. 用同样的查询"有没有适合夏天跑步的鞋？"测试 5 次
3. 记录每次返回的 keywords 是否一致

**思考题：** 为什么结构化提取场景不适合高 temperature？在你的 PHP 后端查询逻辑中，如果 keywords 不稳定会导致什么问题？

### 作业 3: 新增一个意图（理解 Structured Output 的扩展）

当前 `intent` 只支持 search / compare / recommend / info。现在需要你：

1. 新增一个 `wishlist` 意图，表示用户想把商品加入心愿单
2. 在 System Prompt 中描述触发条件
3. 在 PHP 控制器中根据 `intent=wishlist` 做不同的处理（比如返回"已加入心愿单"而不是商品列表）

**思考题：** 如果用户说"这个鞋先帮我存着"，LLM 能正确识别为 wishlist 吗？你需要怎样修改 Prompt 才能让它更准确？
